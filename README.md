# Таблица оценок node-server.ru

Версия Марии Шауловой (группа P4209). Одна статическая страница `index.html`
без собственного сервера: пользователь вводит логин и пароль своей учётной
записи Moodle прямо в браузере, браузер сам обращается к `node-server.ru` —
пароль и выданный токен никуда, кроме Moodle, не отправляются и нигде не
сохраняются (ни в localStorage, ни на каком-либо сервере).

Функции Web Services: `core_webservice_get_site_info`,
`core_enrol_get_users_courses`, `gradereport_user_get_grade_items`. В Moodle
должен быть доступен сервис с этими функциями (на `node-server.ru` он уже
настроен преподавателем).

## Как это работает

1. Форма отправляет логин/пароль на `POST https://node-server.ru/m/login/token.php?service=moodle_mobile_app`
   и получает `wstoken`.
2. Токеном запрашивается `core_webservice_get_site_info` — получаем `userid`.
3. Запрашивается список курсов пользователя (`core_enrol_get_users_courses`).
4. Для каждого курса запрашиваются оценки (`gradereport_user_get_grade_items`)
   и выводятся таблицей: элемент / оценка / диапазон.

Политика `Content-Security-Policy` на странице разрешает сетевые запросы
только на `node-server.ru` — случайная утечка данных на сторонний домен
исключена на уровне браузера.

## Локальная проверка

```bash
npm test
```

Пять тестов: структура обязательных `id`, ограничение CSP на `node-server.ru`,
наличие вызовов всех трёх функций, очистка поля пароля после отправки,
синтаксическая корректность встроенного скрипта.

## Развёртывание

Страница полностью статическая — бэкенд не нужен. Открыть `index.html`
напрямую в браузере нельзя (CSP и некоторые браузеры блокируют `fetch` с
`file://`), поэтому её нужно раздавать по HTTPS. Разместите файл на любом
статическом хостинге или веб-сервере, например тем же nginx, что обслуживает
домен `masha.gifts` — отдельным путём, без привязки к LTI-тренажёру.
